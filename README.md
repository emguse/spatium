# Spatium

工場・倉庫の空間利用を、日付ごとの2Dレイアウトとして編集するブラウザーアプリです。

読み込んだ画像・図面・プロジェクトは全て利用者のブラウザー内で処理され、外部へのデータ送信は行われません。

## 起動

Node.js 22以降で、依存パッケージのインストールなしに起動できます。

```sh
npm run dev
```

http://127.0.0.1:5173 をChromeまたはEdgeで開いてください。配信サーバーはローカルホストにのみ接続し、図面・プロジェクトはブラウザー内で処理します。外部サービス、CDN、解析サービスは使用しません。`dist/` はビルド不要の静的ファイルです。

## 基本操作

1. PNG/JPEGの背景図面を読み込みます。
2. 「2点で縮尺を設定」で既知の距離の両端をクリックし、実寸をmmで入力します。
3. グリッド間隔（初期値100mm）と原点を設定します。
4. 「＋ 配置物」で長方形を作成し、名称・寸法・色・メモを入力します。位置・寸法の入力は最寄りのグリッドに丸めます。固定物は「固定物を編集」から作成します。
5. タイムラインの表示日を選び、配置物を移動します。その日の位置キーフレームが作られ、次の位置変更日まで引き継がれます。移動途中の補間は行いません。
6. 配置物の開始日・終了日で存在期間を指定します。両方の日を含み、終了日が空欄なら無期限です。開始日には必ず初期位置があります。
7. タイムラインは変更日のみを等間隔に表示します。帯が存在期間、◆が位置キーフレーム、終が終了日です。終了日と翌日の両方を列に表示します。任意の日付も選択できます。日付選択だけでは未保存状態になりません。
8. 「保存」で背景を含むJSONをダウンロードします。「開く」で復元、「PNG出力」で選択日の配置を日付付き画像にします。

選択日の配置物・固定物同士が面積をもって重なると、キャンバス上で対象の枠を赤い破線で強調し、「干渉発生中」と重なりペア数を表示します。タイムラインの選択日にも警告アイコンが付きます。辺や角が接するだけなら警告しません。図形にカーソルを合わせると、重なっている相手の名称を確認できます。この警告は配置や保存を妨げず、PNG出力には含まれません。

固定物は全期間共通で、専用モードでのみ編集できます。配置物が登録されている間は背景・校正・グリッド設定を変更できません。配置物の存在期間外でも定義が残っていれば設定のロックは維持します。

新しい配置物の開始日は選択日、終了日は未指定です。複製は選択日の位置と共通属性を持つ新しい配置物を作り、元の位置履歴と終了日は引き継ぎません。重なった状態で作成されるため、選択された複製を移動してください。

開始日の変更は初期位置の日付を移します。後続の位置キーフレームに到達・通過する変更はできません。終了日を最後の位置キーフレームより前にする場合は、先に該当日を選んで位置変更を削除してください。不在期間中は位置を編集できません。

- 「この日まで存在」: 終了日を選択日に設定
- 「選択日の位置変更を削除」: 直前の位置の継承に戻す（開始日の初期位置は削除不可）
- 「配置物を全期間から削除」: 確認後に定義と全履歴を削除
- Ctrl/Cmd + Z: 元に戻す
- Ctrl/Cmd + Shift + Z: やり直す
- Ctrl/Cmd + S: 保存
- Delete / Backspace: 選択中の配置物を全期間から削除する確認
- Esc: 校正・原点指定・ドラッグをキャンセル

自動保存はありません。保存表示はダウンロード要求時に更新します。ブラウザーのダウンロードが完了していることを確認してください。Undo履歴は直近100操作で、ファイルには保存しません。

## データと構成

- `dist/model.js`: データ操作、寸法校正、検証、Undo/Redo
- `dist/app.js`: SVGキャンバス、プロパティ、タイムライン、ローカル入出力
- `dist/style.css`: 作業画面のレイアウト
- `tests/model.test.js`: データモデルの回帰テスト
- `scripts/browser-check.mjs`: ブラウザーを使った一連の操作の回帰テスト

JSONの `version` は2です。**初期モックのversion 1は読み込めません。** 自動移行は行わず、旧形式を選んでも現在の作業は保持します。

`background` に画像とmm/pxの縮尺、`grid` に間隔と背景左上基準の原点、`entities` に共通属性・`startDate`・`endDate`（未指定はnull）・`positionKeyframes`（日付順の `{date, x, y}` 配列）、`fixed` に位置を含む共通固定物を保存します。配置物の位置はグリッド原点を基準とします。背景の左上がX/Y=0、右が+X、下が+Yです。

日付は0001-01-01〜9999-12-31の日単位で、時刻とタイムゾーンを持ちません。選択日はファイルに含めず、開き直すと最初の変更日を表示します。配置物がなければ端末の当日を表示します。

現行の詳細は[設計仕様](docs/spec/current.md)、今後の機能候補は[ロードマップ](docs/roadmap.md)、設計判断は [docs/decisions](docs/decisions)、過去の移行作業は[日付アンカーと存在期間への移行](docs/plan/date-anchored-timeline.md)に記録しています。[初期版の計画](docs/first-step.md)は履歴資料です。

## バージョン管理

アプリのバージョンは `package.json` を正とし、変更履歴は [CHANGELOG.md](CHANGELOG.md) に記録します。現在の次回公開予定版は `0.3.0` です。`0.x` の間は新機能・互換性に影響する変更でマイナーバージョンを上げ、修正やドキュメントのみの変更ではパッチバージョンを上げます。公開時は `main` への反映とPagesデプロイ成功後に `vX.Y.Z` のGitタグを付けます。

プロジェクトJSONの `version` は保存形式の版であり、アプリのバージョンとは独立しています。JSON構造の互換性に影響する変更時のみ更新します。

画像は30MB以下・4,000万画素以下、プロジェクトファイルは60MB以下を受け付けます。PNG出力は図面と配置物を含む範囲を最大約4096pxに縮小し、余白と選択日を付けます。遠くまでズームアウトするとグリッド表示を間引きますが、スナップ間隔は変わりません。

## 検証

```sh
npm test
npm run check
```

ブラウザーテストは、別途Playwrightを利用できる環境で、サーバー起動中に実行します。

```sh
node scripts/browser-check.mjs
```

Playwrightをローカル依存として導入しない場合は `PLAYWRIGHT_MODULE` にそのモジュールパスを指定できます。既存Chromeを使う場合は `CHROME_PATH` に実行ファイルを指定してください。テストは生成した模擬図面を使用し、スクリーンショットとPNGを `artifacts/` に保存します。

オプションのWebMCP対応ブラウザーでは、選択日・存在期間・配置物の位置を読む `read_spatium_layout` を登録します。非対応ブラウザーでは通常のUIのみで動作します。

## 対象範囲

複数存在期間、回転、移動補間、自動再生、PDF、部品パレット、共同編集、3Dなどは現行版に含みません。候補全体は[ロードマップ](docs/roadmap.md)を参照してください。PC・マウス・キーボードを対象にしています。実際の工場・倉庫図面による業務検証は、利用者の図面を使って実施してください。

## GitHub Pages

`main` へのpush時に `.github/workflows/pages.yml` がテストと構文チェックを行い、`dist/` だけをGitHub Pagesに公開します。ビルドや依存パッケージのインストールは不要です。GitHubの Settings → Pages → Source は **GitHub Actions** を使用します。Actionsから手動実行も可能です。
