# 日付アンカーと存在期間への移行

## 方針

時点ごとの配置全体の保存を、**エンティティの存在期間と、日付付きの位置キーフレーム**へ置き換える。

日付は日単位とし、時刻・タイムゾーンは持たない。タイムラインの表示は変更日のみを等間隔に並べ、カレンダー表示は今回含めない。

## データと表示

- 保存形式を `version: 2` とし、可動エンティティに `startDate`、`endDate`、`positionKeyframes` を持たせる。日付は実在する `YYYY-MM-DD` として検証する。
- 開始日は必須、終了日は空欄を許可する。開始日・終了日を含む期間に存在し、終了日なしなら無期限とする。
- 存在期間は1組のみとする。退場後の再登場は別エンティティとして作成する。
- 開始日には必ず初期位置を持つ。それ以後の位置は、選択日以前の最新キーフレームから求める。補間は行わない。
- 同じエンティティの同じ日付には位置を1件だけ保存する。名称・寸法・色・メモは従来どおり全期間で共通とする。
- 固定物は日付と無関係な共通データとして維持する。

## 編集操作

- 任意の日付を選択して配置を表示できる。新規プロジェクトの選択日は端末の当日を初期値とする。
- 配置物を作成すると、選択日を開始日、終了日を空欄とし、その日に初期位置を作る。
- 存在期間中に移動すると、選択日の位置キーフレームを追加・更新する。変更は次のキーフレームまで反映する。現在位置と同じ位置への操作では新規キーフレームを作らない。
- 配置物の複製は新しいIDを作り、選択日の位置・共通属性を複製する。開始日は選択日、終了日は空欄とし、元の位置履歴は複製しない。
- 不在期間では位置編集を無効にし、プロパティから存在期間を変更できる。従来の「この時点に配置」は廃止する。
- 開始日変更時は初期位置の日付を移す。後続キーフレームと同日になる、またはそれを越える変更は拒否する。終了日より後にキーフレームが残る変更も拒否し、理由を表示する。
- 「この日まで存在」「選択日の位置変更を削除」「配置物を全期間から削除」を別操作にする。初期位置は削除不可、全期間削除には確認を設ける。Deleteキーも全期間削除の確認につなぐ。
- 期間変更・キーフレーム編集・削除はUndo／Redoの対象とする。ドラッグ1回は1操作を維持する。

タイムラインの列は、全エンティティの開始日・位置変更日・終了日の翌日を統合し、日付順に表示する。選択日が変更日でない場合は一時的な選択列を表示する。存在期間は帯、位置キーフレームはマーカーで区別し、「変更日の等間隔表示」であることを明示する。

日付順が順序を決めるため、時点の複製・名前変更・並べ替え・削除は廃止する。PNG出力には選択日を記載する。

## 計画・デシジョン・互換性

- `docs/first-step.md` は初期版の履歴として残す。現行仕様は `docs/spec/current.md` を参照する。
- 次の作業計画を `docs/plan/date-anchored-timeline.md` に記録する。
- `docs/decisions/` に、日付と存在期間、位置キーフレームの継承、旧形式非対応の判断をADRとして記録する。
- ADRには状態・背景・決定・代替案・影響を記載する。後日の変更では理由を消さず、新しいADRから旧判断の置き換えを参照する。
- version 1のJSONは移行しない。対応外である旨を表示し、編集中のデータは維持する。新形式の保存・復元・画像出力は同じ日付評価処理を使用する。

## 検証

- 開始日前、開始日、終了日、終了翌日、終了日なしの存在判定。
- 月末・年末・うるう日の扱いと、不正日付・期間逆転の拒否。
- 位置変更のない日では直前の位置を維持し、変更の影響が次のキーフレームで止まること。
- 同日更新、初期位置の保護、期間変更時の矛盾検出、Undo／Redo。
- タイムライン・キャンバス・PNGで選択日の状態が一致すること。
- version 2の往復保存と、version 1・不正データを読み込んでも現在の作業を壊さないこと。
