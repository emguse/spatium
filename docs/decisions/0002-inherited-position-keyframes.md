# ADR 0002: 日付付き位置キーフレームの継承

- 状態: 採用
- 決定日: 2026-09-11
- 関連計画: [日付アンカーと存在期間への移行](../plan/date-anchored-timeline.md)

## 背景

初期モックでは時点ごとに全配置を複製していた。変更のない日を保存せず、配置物の位置の変化だけを編集できるモデルが必要になった。

## 決定

配置物に開始日の初期位置を必須とし、以後は位置が変わる日にキーフレームを保存する。選択日以前の最新キーフレームを存在期間内だけで評価し、補間はしない。位置編集は同日のキーフレームを更新するか、新しいキーフレームを追加する。継承位置と同じ値への操作は新規キーフレームを作らない。

名称・寸法・色・メモは全期間で共通。期間変更、キーフレーム削除、配置物の全期間削除は別操作とする。開始日変更は初期位置の日付を移すが、後続のキーフレームに到達・通過する変更は拒否する。終了日より後にキーフレームを残す変更も拒否し、明示的な整理を求める。

## 代替案

- 配置全体のスナップショット: 編集の独立性は分かりやすいが、後続の変更のない日への反映が難しい。
- 位置の連続補間: 移動途中を表現できるが、今回の工程別配置検討には不要。
- 期間短縮時の自動切り捨て: 操作回数は減るが、利用者の位置変更を暗黙に削除してしまう。

## 影響

途中の日の編集は、次のキーフレームまでの表示も変える。従来の独立した時点の編集とは異なるため、プロパティに反映範囲を示す。初期位置は単独では削除できない。

キャンバス、タイムライン、画像出力で同じ位置評価関数を使用する。Undo／Redoはプロジェクトの編集を対象とし、日付選択は閲覧状態として保持する。

判断を変更する場合は、新しいADRを作成し、本ADRの状態と置き換え先を更新する。
