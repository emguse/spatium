# ADR 0001: 日付アンカーと単一の存在期間

- 状態: 採用
- 決定日: 2026-09-11
- 関連計画: [日付アンカーと存在期間への移行](../plan/date-anchored-timeline.md)

## 背景

初期モックは任意の順序とラベルを持つ時点を扱っていた。工場・倉庫の工程と配置を対応させるため、日付から存在する配置物を求められるようにする。

## 決定

日付を時刻・タイムゾーンなしの `YYYY-MM-DD` で扱う。エンティティは開始日必須・終了日任意の存在期間を1組持ち、両端の日付を含む。終了日なしは無期限とする。固定物は期間から独立して常時表示する。

タイムラインは変更日を等間隔に並べる。開始日・位置変更日・終了日の翌日を列にし、任意の選択日は必要に応じて一時的な列として表示する。日付選択だけではプロジェクトを変更しない。

## 代替案

- 任意ラベルの時点を維持する: 工程の日付との対応が利用者任せになる。
- 終了日を含まない期間: 入れ替えの境界は簡潔になるが、「20日まで存在する」という利用者の指定と一致しない。
- 複数の存在期間: 同じ配置物の再登場を表現できるが、今回の用途では単一期間で十分と判断した。
- 日数に比例したカレンダー: 期間の長さを比較しやすいが、変更のない日が多い計画では表示が広がる。

## 影響

同じ配置物の再登場は別エンティティとして登録する。同日内の順序は表現しない。等間隔表示では列の幅から経過日数を判断できないため、表示方式を画面に明示する。

日付の有効範囲は0001-01-01〜9999-12-31とする。最大日付の翌日は表現範囲外なので、終了日が9999-12-31の場合は不在への切替列を生成しない。

判断を変更する場合は、新しいADRを作成し、本ADRの状態と置き換え先を更新する。

## 補足決定（2026-09-13）

利用確認で終了日そのものを選択しづらいことが分かったため、終了日も列に含め、終了マーカーを表示する。翌日の不在への切替列も残す。終了マーカーは存在期間から導出し、位置キーフレームは自動作成しない。同日に位置変更もある場合は両方を表示する。保存形式と位置の継承規則は変更しない。
